# Content guide — Bihar Board Padhai

Content is separate from the UI. The UI reads only JSON files from `/content`
and never hard-codes a single question, date or syllabus line. This keeps the
door open to a headless CMS (Decap, Sanity) or a Google-Sheets → JSON export
later, without touching React code.

## Folder layout

```
content/
  syllabus.json                           # official subject codes, marks, textbooks, chapter lists (generated)
  sources/bseb_syllabus.raw.json          # research export the syllabus is generated from
  exam-calendar.json                      # board exam dates, each marked official|expected
  papers.json                             # model papers & previous-year papers (links only)
  mock-tests/{class}-{medium}-{subject}-{n}.json
  {class}/{medium}/{subject}/ch-{nn}.json # one file per chapter per medium
```

`{class}` is `class-10` or `class-12`, `{medium}` is `hindi` or `english`,
`{subject}` is the subject id from `src/data/subjects.ts` (e.g. `science`,
`physics`, `history`).

## Chapter file schema

See `src/content/types.ts` (`Chapter`). Key rules:

| Field | Rule |
|---|---|
| `id` | Identical in Hindi and English files, e.g. `c12-phy-ch01`. Progress is tracked by this id. |
| `slug` | URL slug in that medium's language. Hindi medium uses Hinglish (`vaidyut-aavesh`), English uses English (`electric-charges`). |
| `status` | `sample` → `draft` → `reviewed` → `verified_official`. Anything not `verified_official` shows a visible "sample / not official" badge. |
| `source`, `sourceUrl`, `lastReviewed`, `reviewer` | Required on every chapter and every question. |
| `objective[].id` | Globally unique and identical across mediums, e.g. `c12-phy-ch01-q01`. |
| `objective[].options` | Exactly four, in A–D order. `answer` is the index 0–3. |
| `notes` | Blocks: `heading`, `paragraph`, `list`, `formula`, `remember`, `image`. Write in your own words; never paste textbook text. Link the textbook in `textbook.url`. |
| `youtube` | `null` unless a real, licensed lesson exists. |
| `syllabus` | `{ "section": "<section title in syllabus.json>", "no": <chapter number> }` — links the chapter to the official list so it appears in its place on the Subject and Syllabus pages. Required for new chapters. |

Hindi-medium files contain Hindi text only (Devanagari). English files contain
English only. Numbers and formulas may use Latin digits in both.

## Editorial workflow: writer → reviewer → publish

1. **Writer** creates the chapter in both mediums with `status: "draft"` (or
   `sample` for demo material), fills `source` and `sourceUrl`, and runs
   `npm run content:check`.
2. **Reviewer** (a subject teacher) checks every answer and explanation,
   sets `reviewer` and `lastReviewed`, and changes `status` to `reviewed`.
3. **Publish**: only content copied from a cited BSEB document (model paper,
   previous-year paper, official syllabus) may be set to `verified_official`,
   and `sourceUrl` must point to that document. Everything else stays
   `reviewed`.
4. Commit. The build runs `content:check` and fails on schema errors, duplicate
   ids, missing translations (a chapter present in one medium but not the
   other) and broken internal links.

## Syllabus

`content/syllabus.json` is generated by `npm run content:syllabus` from
`content/sources/bseb_syllabus.raw.json`. Each subject carries a `status`:
`verified_official` (from the BSEB syllabus PDF), `verified_textbook` (NCERT book, per
the BSEB rule that electives use NCERT) or `gap` (chapters not yet extracted). The UI
shows every official chapter; chapters without content are marked "coming soon". Fill
gaps by editing the raw file and re-running the import. Class 12 Hindi-medium chapter
names and Class 10 English names are still missing in the source and are shown in the
other language until filled.

## What the checker enforces (`npm run content:check`)

- Every file parses and matches the schema.
- `syllabus.json` exists and every chapter's `syllabus` reference points at a real section and chapter number.
- Chapter ids and question ids are unique across the whole content tree.
- Every chapter id exists in both `hindi` and `english`, with the same number
  of objective and important questions and the same question ids.
- Slugs are unique within a class+medium+subject.
- `examCalendar.json` dates are valid and each entry has a status.
- `sourceUrl` values are `https://` URLs (or empty for sample content) and
  internal `/content/...` image paths exist on disk.
- Writes `src/generated/content-index.json`, the lightweight index the UI
  uses for chapter lists and search.

## Reporting a mistake

Every chapter and question shows a "गलती बताएं / Report a mistake" link that
opens WhatsApp (or mailto) with the chapter id and question id pre-filled.
Fix the JSON, bump `lastReviewed`, and re-run the checker.

## Moving to a CMS later

Each JSON file maps one-to-one to a CMS document with the same fields. Point
`scripts/content-index.ts` at the CMS export directory and nothing in `src/`
changes.
